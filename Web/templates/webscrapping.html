Fase 2

Web Scraping de Precios del m² por Provincia (Tinsa)

La fuente principal de datos de precio del metro cuadrado es Tinsa, la mayor tasadora inmobiliaria de España. El portal publica gráficos de evolución histórica por provincia en formato HTML embebido con JavaScript (Highcharts), sin API pública disponible.

Proceso técnico:

Descarga tinsa.es → Extracción URLs provincias → Request por provincia → Parsing regex → CSV unificado

Paso 1 — Obtención del directorio de provincias: Se descargó la página principal de Tinsa (https://www.tinsa.es/precio-vivienda/) y se guardó como archivo local tinsa.html para procesarla sin realizar peticiones repetitivas. Se aplicó una expresión regular sobre la llamada JavaScript imieAddLocationToMap() que contiene nombre y URL de cada provincia:

pattern = r'imieAddLocationToMap\([^,]+,\s*"([^"]+)",\s*"Provincia",\s*[^,]+,\s*[^,]+,\s*"([^"]+)"' matches = re.findall(pattern, html_content) # Resultado: [("Salamanca", "https://www.tinsa.es/precio-vivienda/castilla-leon/salamanca/"), ...]

Paso 2 — Extracción de datos históricos por provincia: Para cada URL, se realizó una petición HTTP con User-Agent de navegador. El HTML de respuesta incluye el objeto JavaScript de Highcharts con dos arrays: categories (fechas trimestrales) y data (precios en EUR/m²). Se extraen con regex:

dates_pattern = r"categories:\s*\[(.*?)\]" data_pattern = r"data:\s*\[([\d\.,\s-]+)\]" # Heurística de validación: len(data)==len(dates) y todos los valores > 100

Archivos relevantes: web scrapping/tinsa_scraper.py · tinsa.html

Output: CSV con columnas Provincia, Trimestre, Precio_m2 — integrado en el dataset principal del TFM (52 provincias, desde 2005).

Se respetó un time.sleep(1) entre peticiones para no sobrecargar el servidor de Tinsa.

Fase 3

Scraping de Datos Fiscales por Comunidad Autónoma (financialtools)

El asesor hipotecario del portal calcula los impuestos y gastos de compraventa reales según la Comunidad Autónoma del cliente. Los datos proceden de financialtools.web.app, una calculadora pública de hipotecas cuya lógica fiscal está embebida en un fichero JavaScript.

Inspección DevTools → Descarga app.js → Parsing regex JS→Python → Validación manual → Integración Flask

Localización de la fuente: Mediante las DevTools del navegador (F12 → Red → filtro JS) se identificó que toda la lógica fiscal reside en:

https://financialtools.web.app/herramientas/calculadora-hipoteca/app.js

Variables extraídas del fichero JavaScript:

Variable JS Contenido Uso en el portal
itpPorCCAA Tipo ITP por CCAA (4%–10%) — segunda mano Cálculo de impuesto de transmisiones patrimoniales
ajdPorCCAA Tipo AJD por CCAA sobre el capital prestado Actos Jurídicos Documentados de la escritura
gastosNotaria Tabla de aranceles notariales por tramo de precio Estimación gastos de notaría
gastosRegistro Tabla de aranceles registrales por tramo Estimación gastos de registro de la propiedad

Conversión JS → Python: Los objetos JS no son JSON válido (claves sin comillas, comentarios). Se implementó un parser propio con expresiones regulares: eliminación de comentarios, normalización de claves y parseo con json.loads().

text = re.sub(r'//[^\n]*', '', js_block) # Eliminar comentarios de línea text = re.sub(r'/\*.*?\*/', '', text, re.DOTALL) # Eliminar bloques de comentario text = re.sub(r'([{,]\s*)(\w+)(:)', r'\1"\2"\3', text) # Añadir comillas a claves

Archivos relevantes: web scrapping/scraping_finantialtools.ipynb

Fase 5

Integración de IA Generativa — Gemini 2.5 Flash

El portal incorpora dos asistentes conversacionales distintos, ambos sobre Gemini 2.5 Flash (Google DeepMind), con system prompts diferenciados según el perfil del usuario:

Asistente Endpoint Audiencia Contexto inyectado
Asistente Ejecutivo /api/chat Directivos CaixaBank Dataset inmobiliario (muestra), tipos de interés históricos; acceso a Google Search en tiempo real
Noa /api/noa-chat Cliente final Perfil completo del cliente: ingresos, ahorros, DTI, tipo ofrecido, decisión, SHAP contributions
Noa Strategic /api/noa-strategic Gestor bancario Mismo perfil + métricas ML internas (R², RMSE CV, spread base GBR, ajuste por perfil sigmoidal)

Los system prompts instruyen a cada asistente a responder en su rol: el asistente ejecutivo declina preguntas fuera del ámbito de macroeconomía y banca; Noa asesora al cliente sobre su hipoteca concreta; Noa Strategic proporciona argumentos de venta y análisis de riesgo al gestor.
