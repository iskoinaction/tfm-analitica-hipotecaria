1. Variables de Contribución: SHAP TreeExplainer AI Act

Para explicar al cliente el peso exacto de cada variable macroeconómica en su tipo de interés, se emplean valores SHAP (SHapley Additive exPlanations) calculados sobre el modelo GradientBoosting. A diferencia de los coeficientes lineales, SHAP proporciona contribuciones exactas (suman al valor predicho), incluso para modelos no lineales.

Conformidad AI Act (Art. 13-14): SHAP TreeExplainer es un método de explicabilidad model-agnostic que descompone cada predicción individual en la contribución exacta de cada variable. Esto permite al cliente, al gestor y al regulador verificar que no existe discriminación y que el modelo es transparente.
Python — 5. HIPOTECA_PERSONALIZADA_provincial.ipynb (sección 11)Explicabilidad SHAP
# 1. Entrenar GBR con hiperparámetros conservadores
from sklearn.ensemble import GradientBoostingRegressor
import shap

FEATURES = ['Euribor','IPC','Tasa_Paro','Precio_m2','PIB_pc','tasa_ahorro']
TARGET   = 'Spread_Hipotecas'

scaler = StandardScaler()
X_s    = scaler.fit_transform(data[FEATURES].values)

gbr = GradientBoostingRegressor(
    n_estimators=100, max_depth=3, learning_rate=0.06,
    min_samples_leaf=5, random_state=42
)
gbr.fit(X_s, data[TARGET].values)

# 2. Calcular contribuciones SHAP para un cliente específico
explainer   = shap.TreeExplainer(gbr)
shap_values = explainer.shap_values(X_client_scaled)

# 3. Cada valor SHAP indica la contribución EXACTA de esa variable
# al spread predicho. La suma de todos los SHAP + base_value = predicción.
for feat, shap_val in zip(FEATURES, shap_values[0]):
    print(f"{feat}: {shap_val:+.4f}%")

2. Desempeño y Justificación de la Selección del Modelo

Se comparan 6 modelos con TimeSeriesSplit CV-5 (validación temporal que evita data leakage). El GBR no se elige por superar en R² — con cambios estructurales en el spread (crisis 2008-2012, tipos negativos 2016-2020, subida 2022), los R² de CV temporal son negativos para todos los modelos. La selección se basa en:

  • SHAP TreeExplainer proporciona explicabilidad exacta (AI Act Art. 13-14)
  • En RMSE/MAE (error absoluto), GBR es competitivo
  • Captura no-linealidades que los modelos lineales ignoran
  • Hiperparámetros conservadores controlan el sobreajuste
Python — 5. HIPOTECA_PERSONALIZADA_provincial.ipynb (sección 7b)TimeSeriesSplit CV-5 y Selección

3. Defensa Econométrica Previa (ADF y Cointegración)

Antes de proyectar la economía con algoritmos predictivos, el marco XAI exige justificar bajo econometría clásica por qué los tensores temporales se configuran de determinada manera. El uso de la Integración (la letra 'I' en SARIMAX correspondiente al parámetro d=1) no es arbitrario.

Python — 4. econometria_y_demanda_hipotecaria.ipynb (sección 7.2)Test de Estacionariedad Augmented Dickey-Fuller (ADF)
from statsmodels.tsa.stattools import adfuller

# 1. Test de Raíz Unitaria sobre variable en bruto (Nivel 0)
result_nivel = adfuller(df['Tasa_Paro'].dropna())
print(f"ADF Nivel 0 -> P-Value: {result_nivel[1]:.4f}")

# 2. Test sobre la Primera Diferencia (Nivel 1)
result_diff = adfuller(df['Tasa_Paro'].diff().dropna())
print(f"ADF Diferenciado (d=1) -> P-Value: {result_diff[1]:.4f}")
Interpretación EconométricaADF Nivel 0 -> P-Value: 0.3852 (No Estacionaria. Media variante) ADF Diferenciado (d=1) -> P-Value: 0.0150 (Estacionaria. Rechaza Ho al 95%) [CONCLUSIÓN]: La serie contiene una Raíz Unitaria. Proyectarla en bruto produciría Varianza Infinita. Al forzar el hiperparámetro d=1 en el SARIMAX a continuación, garantizamos que el algoritmo trabaje sobre los *incrementos* estables de la serie, eliminando el ruido de tendencia a largo plazo.
Selección por Backtesting y Prevención de Regresión Espuria: Para la fase de extrapolación macroeconómica se ha adoptado una estrategia de selección por backtesting que asigna a cada variable el método que mejor se comporta sobre datos que los modelos no han visto (período de test: 2017Q1–2019Q4). Los modelos de Machine Learning basados en árboles son excelentes interpoladores dentro de los rangos entrenados, pero fuera de esos rangos tienden a dar respuestas planas. Los modelos econométricos (SARIMA, ARIMA) capturan mejor las tendencias y estacionalidades de cada serie individual.

3.1 Algoritmos de Extrapolación Temporal BACKTESTING

Se compararon 6 modelos (ARIMA, SARIMA, Prophet, VAR, ETS, Seasonal Naive) sobre cada variable macroeconómica. El ganador cambia según la naturaleza de cada serie, lo que confirma la pertinencia de la estrategia mixta:

  • Euríbor e IPC (Escenarios BCE / Forward Guidance): Determinados por decisiones del Consejo de Gobierno del BCE y shocks exógenos (energía, geopolítica). Ningún modelo de series temporales puede anticiparlos con fiabilidad. Se utilizan directamente las proyecciones macroeconómicas publicadas por el BCE y el FMI.
  • PIB per cápita → SARIMA(1,1,0)(1,1,0)4: El ciclo trimestral del PIB tiene una estructura estacional muy marcada que solo los modelos con componente estacional explícito capturan. SARIMA obtiene el menor error con un MAPE del 0.6%, frente al 0.8% de Prophet y errores 4x superiores del resto.
  • Tasa de Paro → Auto-ARIMA (AIC) + Suelo 8.5%: ARIMA queda prácticamente empatado con VAR y Prophet (RMSE ≈ 0.75). Se selecciona ARIMA con optimización automática del orden (p,d,q) por criterio AIC. Se aplica un suelo estructural del 8.5% basado en factores exógenos ceteris paribus.
  • Precio del m², Población, Pob. Extranjera y Transmisiones → Holt-Winters (Exponential Smoothing): Tras el duelo de modelos "naive", se ha decidido usar Holt-Winters para todas las variables volumétricas y de precios por cuatro razones críticas:
    • Dominio Aplastante: HW gana en las variables más pesadas: Precio_m2 (79% de mejora) y Población (74% de mejora).
    • Visión a Largo Plazo: El Seasonal Naive proyecta una línea plana, mientras que HW entiende la tendencia y el crecimiento.
    • Consistencia: Es mucho más robusto presentar un pipeline único y coherente.
    • Marginalidad: Aunque el Naive ganó en ventas por un mínimo 0.8%, HW suaviza mejor el ruido.

3.2 Modelo de Demanda Hipotecaria Notebook 4

El volumen hipotecario (número de hipotecas formalizadas) se predice con un enfoque distinto al del pricing. El notebook 4. econometria_y_demanda_hipotecaria.ipynb implementa un benchmark completo de 6 enfoques sobre el panel de 52 provincias (2005-2025):

  • Corrección de Data Leakage: Las variables contemporáneas al target (Precio_m2, Transmisiones_Total, Spread_Hipotecas) se convierten en lags (t-1 y t-4) para evitar filtración de información futura.
  • Benchmark Provincial → Agregado: Predecir por provincia y sumar. Acumula errores (MAPE nacional ~9.7%).
  • RF_Nac (Modelo Ganador): Random Forest entrenado directamente sobre datos agregados nacionales con feature engineering rico. MAPE 7.1%, R² 0.40 (único enfoque con varianza explicada positiva).
  • SARIMAX: Series temporales clásico como alternativa econométrica. Comparado directamente contra RF_Nac en el mismo período de test.
  • VAR + IRF (Funciones de Impulso-Respuesta): Modelo vectorial que cuantifica cómo responde el volumen hipotecario ante shocks de ±1 unidad en Euribor, PIB y precio m² a lo largo de 12 trimestres.
Conclusión (Notebook 4, Sección 7.3): Los tests de cointegración de Johansen confirman que las variables hipotecarias presentan relaciones de largo plazo. Sin embargo, la heterogeneidad provincial y la ausencia de cointegración global descarta el uso de un VECM conjunto: se opta por modelos ML (RF_Nac) para la predicción nacional y SARIMA individuales por provincia.

4. Modelo Principal: Pricing Hipotecario GBR + SHAP

Para determinar el tipo exacto (Spread óptimo) sugerido para un cliente, el sistema ejecuta un Gradient Boosting Regressor entrenado sobre el dataset completo (4.368 observaciones, 52 provincias, 2005-2025) y aplica un ajuste por perfil basado en el ratio ingresos/PIB_pc provincial. Fuente: 5. HIPOTECA_PERSONALIZADA_provincial.ipynb (sección 11).

Anti-Overfitting y Explicabilidad: El pipeline usa max_depth=3 (máximo 8 hojas por árbol), min_samples_leaf=5, y learning_rate=0.06 (100 árboles con aprendizaje lento). SHAP TreeExplainer descompone cada predicción en la contribución exacta de cada variable — cumpliendo AI Act sin sacrificar capacidad no-lineal.

def _calc_income_adjustment(income, pib_pc):
    """Ajuste sigmoidal (tanh) por perfil del cliente."""
    income_ratio = (income * 12) / pib_pc
    x = (income_ratio - 1.0) * 2.0
    adj = -0.25 * np.tanh(x)       # ratio > 1 → bonificación
    if income_ratio < 0.5: adj += 0.05  # penalización extra
    return round(adj, 4)

5. Regulación Final: Maximización Comercial vs DTI CaixaBank

El algoritmo anterior nos dará lo que la máquina "cree que podemos cobrar" como Spread en función del mercado macro. Sin embargo, no podemos encasquetarle ese tipo al perfil del cliente de la web si hace que su cuota exceda los topes regulatorios de Banco de España y riesgos inter-bancarios. Entra en escena el filtro final de nuestro código de backend:

Python — Producción Backend (app.py)Acotamiento de Oferta vs Tope de Ingresos (DTI) con Búsqueda Binaria
def _compute_ml_optimal_rate(...):
    # 1. Extraer spread "Puro" comercial que sugiere el modelo entrenado antes
    x_s = scaler.transform([[macro_vals[f] for f in FEATURES]])
    ml_spread = max(float(model.predict(x_s)[0]), 0.1) # Min 0.1 banco como piso
    ml_rate_raw = euribor + ml_spread

    # 2. Límite de Viabilidad Bancaria: Máximo Dinero mensual libre para el DTI < 35%
    max_cuota = max(0, 0.35 * income - other_debts)

    dti_max_rate = ml_rate_raw  
    if max_cuota > 0 and loan > 0:
        
        # 3. Búsqueda binaria O(log N) de la asintótica de la Tasa
        lo, hi = 0.001, 0.25  # Evaluar TIN desde 0.1% a 25% anual
        for _ in range(50):
            mid = (lo + hi) / 2
            mr = mid / 12     # Desplazar a tasa mensual
            
            # Proyección geométrica de la anualidad (Ecuación Canónica de Préstamo)
            cuota_mid = loan * mr * (1 + mr)**n_months / ((1 + mr)**n_months - 1)
            
            # Subir o bajar el límite
            if cuota_mid <= max_cuota: lo = mid
            else: hi = mid
            
        dti_max_rate = round(lo * 100, 4) # Tasa máxima biológicamente soportable

    # 4. Decisión de la IA XAI
    # El banco intenta exprimir beneficio usando ML (ml_rate_raw), 
    # pero obligamos matemáticamente a frenarlo por debajo del ahogamiento del cliente
    ml_rate_capped = min(ml_rate_raw, dti_max_rate)
    
    return {'ml_rate': ml_rate_capped}
